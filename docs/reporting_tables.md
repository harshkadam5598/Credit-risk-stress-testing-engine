# Reporting tables and Power BI guide

The pipeline writes the tables below to `outputs/`. Column-by-column definitions and data types are in `data_dictionary.md`; this guide covers what each table is for, how the tables relate, how to label results, how to build the three report pages, and how to import, refresh and reconcile. The project owner builds the report as `Credit_Risk_Stress_Testing.pbix` in the repository root (not yet added); GitHub cannot display `.pbix` files interactively, so screenshots can give a preview and the file is opened in Power BI Desktop.

Conventions: CSV, UTF-8, snake_case names, ISO dates, probabilities as 0 to 1 decimals, currency as plain GBP numbers, stable column names and order across reruns. **An empty cell means "suppressed or not applicable", never zero.**

## 1. Table inventory

Row counts are from the reference run (seed 20261002).

| Table (file) | Grain | Key | Rows | What it contains | Used on page |
| --- | --- | --- | --- | --- | --- |
| `loan_predictions` | one row per loan | `loan_id` | 15,000 | Baseline PD, band, EAD, LGD, EL, observed outcome, segment fields | 1 |
| `portfolio_summary` | scenario × segment type × segment value | `scenario_id`, `segment_type`, `segment_value` | 123 | Aggregates of PD, EAD, EL for baseline, adverse, severe adverse | reconciliation; optional on 1 and 3 |
| `scenario_results` | one row per loan per scenario | `loan_id`, `scenario_id` | 45,000 | Loan-level PD, EAD, LGD, EL, band under each scenario | 3 |
| `scenario_assumptions` | scenario × driver | `scenario_id`, `driver` | 21 | Shocks applied and variables held constant | 3 |
| `sensitivity_results` | one row per multiplier | `multiplier` | 5 | Portfolio results for 0.5 to 3.0 times the severe shock | 3 |
| `model_metrics` | model × dataset × metric | `model_id`, `dataset`, `metric` | 59 | Metrics with intervals; paired differences | 2 |
| `calibration_bins` | model × dataset × bin | `model_id`, `dataset`, `bin` | 10 | Predicted versus observed default rate by bin | 2 |

The full reporting tables are regenerated by the pipeline and are git-ignored.

## 2. Compact sample for demonstration and import testing

`data/sample/reporting/` holds one `<table>_sample.csv` for each table above (about 66 KB in total). **These are samples, not complete data.** They are written by `python run_pipeline.py --stage export`, only after the full-table contract has passed, and each is checked (the export stage executes 57 sample checks).

| Sample file | What it holds |
| --- | --- |
| `loan_predictions_sample`, `scenario_results_sample` | All loans of the first 100 customers (150 loans), the same loans as `data/sample/loan_data_sample.csv`, with their three scenario rows each (450 rows) |
| `portfolio_summary_sample` | Full-portfolio rows for the `portfolio`, `data_split` and `risk_band` views, for all three scenarios (24 rows) |
| `model_metrics_sample` | Test and out-of-fold rows for `roc_auc`, `brier`, `log_loss`, `calibration_slope`, `calibration_ratio`, plus the three paired-difference rows (23 rows) |
| `segment_performance_sample` | All 8 reported segments and the first 4 `insufficient_data` segments (12 rows) |
| `scenario_assumptions_sample`, `sensitivity_results_sample`, `calibration_bins_sample`, `model_coefficients_sample`, `metric_definitions_sample` | Complete (these tables are tiny) |

What was verified: exact schemas and column order as the full tables; every sample row is an exact text copy of a row in the full table; keys are unique; the loan sample matches the raw-data sample; every sampled loan has exactly three scenario rows and baseline PDs match `loan_predictions_sample`; EL = PD × LGD × EAD on every row; suppressed intervals are empty and reported ones are populated.

**Intended use.** Prototype the Power BI data model, relationships, measures and visuals; test import, types and refresh; demonstrate the report structure. **Do not use the samples for totals or reconciliation:** the loan-level sample covers 150 loans, whereas the aggregate samples are rows from the full 15,000-loan portfolio, so they do not reconcile to each other. Use the full tables for any number that is reported. To switch from sample to full data, change the folder parameter and drop the `_sample` suffix from the file names (see section 7).

## 3. What each number is: facts, model outputs, hypothetical results

Every figure in the report must be one of these three kinds and be presented as such.

| Kind | Where it appears | How to recognise it | How to present it |
| --- | --- | --- | --- |
| **Observed (simulated) facts** | `default_status` in `loan_predictions`; `observed_defaults` and `simulated_realised_loss` in baseline `portfolio_summary` rows; `observed_rate` in calibration, segment and metric tables | Outcomes drawn in the simulation | "Observed (simulated) outcome". Never a scenario result |
| **Model outputs on the baseline book** | `pd_12m`, `risk_band`, `expected_loss` in `loan_predictions`; `portfolio_summary` rows with `result_type = baseline_estimate`; `model_metrics` | Model estimates for the T0 portfolio | "Model estimate". EL is illustrative |
| **Hypothetical stress results** | `scenario_results` and `portfolio_summary` rows for adverse and severe adverse (`result_type = hypothetical_stress`); all of `sensitivity_results` (`result_type = hypothetical_sensitivity`) | Anything shocked | Label on every visual: "Hypothetical stress result, not a forecast". Never call stressed defaults or losses realised |

Observed outcome columns are empty for adverse and severe-adverse rows by design. The baseline scenario in `scenario_results` equals the baseline model estimate (zero shock). Development-loan PDs are in-sample, so use `data_split` to show development and test separately and treat test loans as the independent evidence.

## 4. Data model

Create a small scenario table in Power Query: from `scenario_assumptions` keep `scenario_id`, `scenario_name`, `scenario_type`, remove duplicates, and add a sort-order column (baseline 1, adverse 2, severe adverse 3). Call it `DimScenario`. Optionally create a small model table (distinct `model_id`).

| From (one side) | To (many side) | Column | Filter direction |
| --- | --- | --- | --- |
| `loan_predictions` | `scenario_results` | `loan_id` | single (loan to scenario rows) |
| `DimScenario` | `scenario_results` | `scenario_id` | single |
| `DimScenario` | `portfolio_summary` | `scenario_id` | single |
| `DimScenario` | `scenario_assumptions` | `scenario_id` | single |
| model table (optional) | `model_metrics`, `calibration_bins`, `segment_performance`, `model_coefficients` | `model_id` | single |

`sensitivity_results` and `metric_definitions` stand alone. Avoid many-to-many relationships. Because `portfolio_summary` is pre-aggregated, slicers on loan attributes (region, purpose) do not filter it; build visuals that need such slicers from the loan-level tables, and keep `portfolio_summary` for fixed aggregates and reconciliation.

## 5. Measures

Rules: rates are **ratios of sums, never averages of rates**; `portfolio_summary` stores several views of the same loans, so filter `segment_type` to one value (use `portfolio`) before summing; show `n_loans` and `n_defaults` beside any rate. The DAX below follows standard syntax but has **not been executed** (there is no Power BI environment in this project). Adapt table and column names if you rename them.

Add two helper columns first (Power Query or calculated columns):

```
loan_predictions[Baseline Band Rank] = VALUE ( RIGHT ( loan_predictions[risk_band], 1 ) )
scenario_results[Band Rank]          = VALUE ( RIGHT ( scenario_results[risk_band], 1 ) )
scenario_results[Baseline Band Rank] = RELATED ( loan_predictions[Baseline Band Rank] )
```

Baseline portfolio measures (page 1, from `loan_predictions`):

```
Loans                  = COUNTROWS ( loan_predictions )
Total EAD              = SUM ( loan_predictions[ead] )
Expected Loss          = SUM ( loan_predictions[expected_loss] )
EL Rate                = DIVIDE ( [Expected Loss], [Total EAD] )
Expected Defaults      = SUM ( loan_predictions[pd_12m] )
Mean PD                = AVERAGE ( loan_predictions[pd_12m] )
EAD-weighted PD        = DIVIDE ( SUMX ( loan_predictions, loan_predictions[pd_12m] * loan_predictions[ead] ), [Total EAD] )
Observed Defaults      = SUM ( loan_predictions[default_status] )
Observed Default Rate  = DIVIDE ( [Observed Defaults], [Loans] )
Expected / Observed    = DIVIDE ( [Expected Defaults], [Observed Defaults] )
Simulated Realised Loss = SUMX ( loan_predictions, loan_predictions[default_status] * loan_predictions[lgd] * loan_predictions[ead] )
```

Scenario measures (page 3, from `scenario_results`; hypothetical):

```
Scn Loans              = COUNTROWS ( scenario_results )
Scn EAD                = SUM ( scenario_results[ead] )
Scn EL                 = SUM ( scenario_results[expected_loss] )
Scn EL Rate            = DIVIDE ( [Scn EL], [Scn EAD] )
Scn Expected Defaults  = SUM ( scenario_results[pd_12m] )
Scn Mean PD            = AVERAGE ( scenario_results[pd_12m] )
Scn EAD-weighted PD    = DIVIDE ( SUMX ( scenario_results, scenario_results[pd_12m] * scenario_results[ead] ), [Scn EAD] )
Baseline EL            = CALCULATE ( [Scn EL], DimScenario[scenario_id] = "baseline" )
EL Change vs Baseline  = [Scn EL] - [Baseline EL]
EL Change %            = DIVIDE ( [EL Change vs Baseline], [Baseline EL] )
EL Rate Change (pp)    = [Scn EL Rate] - CALCULATE ( [Scn EL Rate], DimScenario[scenario_id] = "baseline" )
Mean PD Change (pp)    = [Scn Mean PD] - CALCULATE ( [Scn Mean PD], DimScenario[scenario_id] = "baseline" )
Loans Moving Up        = CALCULATE ( COUNTROWS ( scenario_results ), FILTER ( scenario_results, scenario_results[Band Rank] > scenario_results[Baseline Band Rank] ) )
Share Moving Up        = DIVIDE ( [Loans Moving Up], [Scn Loans] )
```

Model-evidence measures (page 2, from `model_metrics` and `segment_performance`):

```
Metric Value  = MAX ( model_metrics[value] )
CI Text       = IF ( ISBLANK ( MAX ( model_metrics[ci_lower] ) ), "n/a",
                     FORMAT ( MAX ( model_metrics[ci_lower] ), "0.000" ) & " to " & FORMAT ( MAX ( model_metrics[ci_upper] ), "0.000" ) )
Segment AUC   = IF ( MAX ( segment_performance[interval_status] ) = "reported",
                     FORMAT ( MAX ( segment_performance[auc] ), "0.000" ), "insufficient data" )
```

## 6. Page guidance

**Global.** Use one consistent colour for baseline, one for adverse and one for severe adverse. Show a footer on every page: "Synthetic data for a fictional bank. Illustrative prototype, not for lending decisions." Format money as GBP with no decimals, probabilities and rates as percentages with two decimals, counts as whole numbers. Use `metric_definitions` for tooltips.

### Page 1: Portfolio Risk Overview (baseline model estimates)

| Visual | Fields | Notes |
| --- | --- | --- |
| KPI cards | Loans, Total EAD, Expected Loss, EL Rate, Mean PD, EAD-weighted PD | Subtitle "Model estimate, baseline" |
| Table: expected vs observed by `data_split` | `data_split`, Loans, Expected Defaults, Observed Defaults, Expected / Observed | Highlight that `test` is independent evidence and `dev` is in-sample |
| Column chart: loans and EL by risk band | `risk_band`, Loans, Expected Loss | Order B1 to B5 |

| Slicers | `data_split`, `region`, `loan_purpose` | Slicers filter all loan-level visuals |

### Page 2: Model Performance & Validation (model evidence)

| Visual | Fields | Filters and notes |
| --- | --- | --- |
| Metrics matrix: logistic vs gradient boosting | rows `metric`, columns `model_id`, values Metric Value and CI Text | Page filter `dataset = test`; metrics `roc_auc`, `pr_auc`, `ks`, `brier`, `log_loss`, `calibration_slope`, `calibration_ratio`, `capture_top10`, `capture_top20` |
| Paired differences table | rows with `model_id = gradient_boosting_minus_logistic`: Metric Value, CI Text | Explain the sign conventions from `metric_definitions` |

### Page 3: Stress Testing (all hypothetical)

Place a banner at the top: **"Hypothetical stress scenarios. What-if results from a model on synthetic data. Not forecasts. EAD, LGD and credit score are held fixed."** Show it on every visual's subtitle or the page header.

| Visual | Fields | Notes |
| --- | --- | --- |
| KPI cards by scenario | Scn EL, Scn EL Rate, Scn Expected Defaults, Scn Mean PD by `DimScenario[scenario_name]` | Baseline card labelled "Model estimate"; others "Hypothetical" |
| Column chart: EL by scenario | `DimScenario[scenario_name]`, Scn EL | Data labels on |
| Change table | scenario, EL Change vs Baseline, EL Change %, EL Rate Change (pp), Mean PD Change (pp) | |
| Risk-band distribution | `scenario_results[risk_band]`, Scn Loans, legend `scenario_name` | Edges are fixed from the baseline, so band movement is real |
| Migration matrix | rows `loan_predictions[risk_band]` (baseline band), columns `scenario_results[risk_band]`, value Scn Loans | Single-select scenario slicer (adverse or severe adverse); add Share Moving Up as a card |

Never present stressed defaults or losses as realised. Observed outcomes belong only on baseline visuals.

## 7. Import and refresh

1. From the repository root, create or refresh the tables: `python run_pipeline.py --stage all` (or from the changed stage onward, see the README). Then `python run_pipeline.py --stage export` confirms the contract and refreshes the samples.
2. In Power BI Desktop use Get data, Text/CSV for each table (or the Folder connector filtered to those files). Use a parameter for the folder path, and a second for the file suffix (empty for the full tables, `_sample` for the samples).
3. Set types explicitly: text for IDs and categories (including `term_months`, `origination_year` and `segment_value` when used as labels), decimal for amounts and probabilities, whole numbers for counts. Leave blanks as null.
4. After re-running the pipeline use Refresh. Column names and order are stable. If the `export` stage fails, do not refresh until it passes.

## 8. Reconciliation

Run these on the **full tables**, not the samples. Any difference found in the report is a difference introduced in the report model, because the `export` stage already checks the files.

**Instructions.**
- Sum `loan_predictions[expected_loss]` and compare with the baseline `portfolio` row of `portfolio_summary`.
- For each scenario, sum `scenario_results[expected_loss]` and compare with the `portfolio` row of `portfolio_summary` for that scenario.
- `n_loans`, EAD and EL summed over any single `segment_type` must equal the portfolio total.
- The sensitivity row with multiplier 1.0 must equal the severe-adverse scenario.
- EAD and LGD must be identical across scenarios.
- Test-set values on page 2 must equal the `dataset = test` rows of `model_metrics`.
